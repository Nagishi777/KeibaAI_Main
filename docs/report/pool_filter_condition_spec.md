# 条件仕様書: 賭け1m / pool_1m q0.75 / all / ev1.10

作成日: 2026-09-16
対象条件: **回収率 161.43% [109.3, 225.4]**（1,508点 / 758レース / 損益 +93,631円）

本書は「この条件が具体的に何をやっているか」を、実際に使っている値とともに記述する。

> **IMPORTANT: この条件は実運用の推奨ではない。**
> 単一分割・多重比較（108条件の探索）を含む調査結果であり、
> walk-forward による期間安定性は未検証。§8 の限界を必ず読むこと。

---

## 1. 全体像

```
[1] 5m時点と1m時点のオッズ・総票数を取得
      ↓
[2] 馬番別の投票額を逆算（オッズの定義式から）
      ↓
[3] 特徴量2列を作る: odds_1m / inc_share_5m_1m
      ↓
[4] LightGBMで各馬の勝率を予測（4本の木）
      ↓
[5] 【フィルタ】1m時点のレース総額が 7.39億円未満のレースは丸ごと見送る
      ↓
[6] 残ったレースで EV = 予測確率 × 1mオッズ ≥ 1.10 の馬を買う
      ↓
[7] 賭け金は fractional Kelly（0.1）で決定、1レース最大3点
      ↓
[8] 払戻は確定払戻金で計算
```

## 3. 特徴量（2列のみ）

### 3.1 前段: 馬番別の投票額を逆算する

JRAの単勝オッズの定義式から逆算する（`src/features/market/odds_series_loader.py` の `estimate_votes`）。

```
オッズ_i = (1 - 控除率0.20) × レース総投票額 / 投票額_i

→  投票額_i = 0.8 × レース総投票額 / オッズ_i
```

`レース総投票額`は `hyosu_total`（百円単位の累計票数）。これを5m時点・1m時点それぞれで計算する。

### 3.2 使う2列

| 列名 | 定義 | 意味 |
|---|---|---|
| `odds_1m` | 1m時点の単勝オッズ（生の値。変換しない） | 市場の**水準** |
| `inc_share_5m_1m` | `max(投票額_1m - 投票額_5m, 0) / Σ_j 同` | 直前1分の資金の**勢い** |

`inc_share_5m_1m` は「5m→1m の間にレース全体へ入った新規資金のうち、この馬が占めた割合」。

> **NOTE: `votes_share` を使わない理由**
> `votes_share_{時点}`（その時点の投票額シェア）は、計算過程で総投票額が
> 約分されて `(1/オッズ_i) / Σ(1/オッズ_j)` になり、**市場確率シェアと
> 相関1.000000で完全一致**する。つまり「投票データ」ではなく単なるオッズの
> 言い換えなので、本条件では生オッズ（`odds_1m`）を直接使い、
> 差分である `inc_share` と役割を明確に分けている。

### 3.3 実際の値（例: race_id=202610020712 / 2026-07-18）

| 馬番 | odds_5m | **odds_1m** | 5m投票額 | 1m投票額 | 流入額 | **inc_share_5m_1m** | 着順 |
|---|---|---|---|---|---|---|---|
| 5 | 1.3 | **1.6** | 2億7,260万 | 4億5,012万 | 1億7,752万 | **0.3839** | **1着** |
| 6 | 12.3 | **7.3** | 2,881万 | 9,866万 | 6,984万 | **0.1511** | 5着 |
| 10 | 15.1 | **9.5** | 2,347万 | 7,581万 | 5,234万 | **0.1132** | 7着 |
| 7 | 9.7 | **8.5** | 3,653万 | 8,473万 | 4,819万 | **0.1042** | 2着 |
| 8 | 30.1 | **16.5** | 1,177万 | 4,365万 | 3,187万 | **0.0689** | 6着 |
| 13 | 16.9 | 16.1 | 2,097万 | 4,473万 | 2,376万 | 0.0514 | 4着 |
| 3 | 121.0 | 138.3 | 293万 | 521万 | 228万 | 0.0049 | 13着 |

6番はオッズが 12.3 → 7.3 に急落し、流入シェア0.151 を獲得している。

**この「直前1分でどこに金が向かったか」が特徴量の中身である。**

## 4. モデル

| 項目 | 値 |
|---|---|
| アルゴリズム | LightGBM（binary / metric=auc） |
| 入力列 | `odds_1m`, `inc_share_5m_1m` の2列のみ |
| `num_leaves` | 15 |
| `max_depth` | 4 |
| `learning_rate` | 0.03 |
| `min_data_in_leaf` | 200 |
| `feature_fraction` / `bagging_fraction` / `bagging_freq` | 1.0 / 0.9 / 1 |
| `lambda_l1` / `lambda_l2` | 0.0 / 1.0 |
| **実際に育った木の本数** | **4本**（early stopping） |
| 検証AUC | **0.8403** |
| importance | `inc_share_5m_1m`: 741,866 / `odds_1m`: 4,422 |

> **NOTE: 木を小さくしている理由**
> config既定（`num_leaves: 113` / `min_data_in_leaf: 100`）は2列に対して
> 木が大きすぎ、**1本目でholdout AUCが飽和して early stopping が即発動し
> `num_trees=1`** になる（片方の特徴量の importance が 0 になる）。
> 2列モデルには小さい木が必要。

importance比は 99.4 : 0.6 で、実質 `inc_share_5m_1m` が予測を支配している。

**サンプルウェイト**: 時間減衰（`recent_years: 2.0` / `mid_years: 4.0` / `w_recent: 3.0` / `w_mid: 2.0`）

**キャリブレーション**: isotonic。学習期間末尾のholdout（22,696行）でfitし、検証期間は使わない。

## 5. フィルタ: `pool_1m` q0.75

### 5.1 何を見ているか

`pool_1m` = **1m時点のレース総投票額（円）** = `hyosu_total_1m × 100`

レース単位の値で、同一レースの全馬に同じ値が入る。

### 5.2 しきい値の決め方（未来を見ない）

**学習期間（2024-01〜2025-07）の5,095レースの分布**から75%分位点を取り、その**固定値**を検証期間に適用する。検証期間の分布は参照しない。

学習期間のレース総額の分位点:

| 分位点 | 1m時点レース総額 |
|---|---|
| q0.00（最小） | 2億1,994万円 |
| q0.25 | 4億4,677万円 |
| q0.50（中央） | 5億5,087万円 |
| **q0.75 → 採用しきい値** | **7億3,920万円** |
| q0.90 | 11億3,991万円 |
| q1.00（最大） | 408億1,138万円 |

### 5.3 適用結果

```
pool_1m ≥ 739,195,000円 のレースだけを賭け対象にする
```

| 項目 | 値 |
|---|---|
| 検証期間の全レース | 3,230レース |
| **フィルタ通過** | **945レース（29.3%）** |
| 通過した行数 | 13,470行 |

検証期間の約7割のレースを**丸ごと見送る**。

### 5.4 なぜ特徴量ではなくフィルタなのか

`pool_1m` をモデルの特徴量に加えると回収率が **-22〜-31ポイント悪化**した。
レース内の全馬に同じ値が入るため馬の序列化に寄与せず、木が無駄な分割を
消費して確率の校正が壊れるため（AUCは変わらず回収率だけ低下）。

一方フィルタとして使うと機能する。**レース内の序列化とレース間の選別は
別の仕事**であり、プール規模は後者にのみ効く。厚いプールのレースは
オッズが安定し `inc_share` の信号も信頼できるが、薄いプールでは
少額の投票でシェアが大きく動きノイズが乗る。

## 8. 限界（重要）

1. **多重比較のバイアス**: 3フィルタ × 4分位 × 3帯 × 3 min_ev = 108条件を
   試した中の上位条件である。この161.43%は上方バイアスを持つ。

2. **単一分割**: 検証は2025-08〜2026-07の12ヶ月・758レースのみ。
   期間依存性は未検証。過去の類例では、単一分割で107%だった条件が
   walk-forward 12フォールドでは100.3%まで落ちた（`final_votes_backtest_report.md` §7.2）。

3. **的中率3.85%の高分散戦略**: 平均オッズ80.3倍で、58点の的中が
   全ての利益を生んでいる。少数の高配当に依存する構造。

4. **フィルタで7割のレースを捨てる**: 945/3,230レースしか賭けない。
   点数が減るぶん分散は大きくなる。

5. **1m時点で発注できる前提**: 実際の投票締切は発走の約1〜2分前。
   1mオッズを見て発注する時間的余裕があるかは運用側の検証が必要。

6. **2列の相関**: `odds_1m` と `inc_share_5m_1m` は相関が高く、
   importance比も99.4:0.6。実質1列モデルに近い。
